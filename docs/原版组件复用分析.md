# 原版组件仓库与组件复用

分析及实测日期：2026-09-27；原包版本：iTab 2.3.13；新工程版本：1.0.1。

## 结论与当前实现

原版在线组件目录可以直接读取，部分原版组件可以作为在线页面使用。新工程已在「添加组件 → 原版组件仓库」接入真实目录，支持搜索、刷新、仅显示可用项、添加到当前分组、打开原版页面及备份入口。

本次接口返回 50 项，其中 18 项使用 `insetType=iframe`，新工程支持添加这 18 类在线入口。另 32 项依赖原扩展的本地组件宿主，列表显示「原版内置组件 · 待适配」，不能直接添加。**原版 PDF 和 AiPPT 均保留在目录中，没有专项过滤；删除的仅是新工程的本地功能与默认入口。**按用户要求，没有旧主页迁移代码。

这不是把全部原版组件源码移植完成，也没有把原版账号、会员、同步或自动更新机制接入新工程。

## 三种不同的“复用”

| 对象                       | 能否直接使用                     | 本次实现                                            |
| -------------------------- | -------------------------------- | --------------------------------------------------- |
| 原版在线目录               | 当前可以；匿名 GET 实测成功      | 读取真实 JSON，展示完整条目，支持搜索与刷新         |
| 原版独立在线页面           | 原站允许嵌入且页面依赖可用时可以 | 接入 18 类已核实入口，点击主页图标打开隔离的 iframe |
| 原版主页动态卡片及内置弹窗 | 不能单拷贝一个编译文件即运行     | 保留 12 类本地组件；原版内置条目标记待适配          |

例如「下一个假期」可以打开原版在线页面，但主页上当前显示的是入口图标，并没有复制原版动态卡片的 Vue 实现。「天气」「日历」「备忘录」仍使用新工程已有的本地实现。

## 目录接口与证据

`chunks/index-DBxDqQ97.js` 中的 `WidgetList` 使用 `widget/list`，参数包括 `name`、`category`、`size` 和 `page`；它是原版 UI 所称的小组件仓库，不是 GitHub 源代码仓库。

本次请求：

```text
GET https://base.itab.link/widget/list?category=widget&size=100&page=1&lang=cn
```

未附带 token、设备指纹或签名，返回 HTTP 200、业务 code 200、count 50，响应允许跨域读取。原客户端 `baseRequest-Yj83uNvm.js` 会附加签名、版本、设备信息及可选 token，但本次公开目录请求不需要复制这些客户端凭据。这不表示所有原版业务接口都支持匿名访问。

原始快照见 [original-widget-catalog.json](original-widget-catalog.json)，页面状态记录见 [original-widget-endpoints.json](original-widget-endpoints.json)。在线目录可能由原服务更新，50/18 是本次实测数量。当前一次最多读取 100 项，后续若目录扩大，需要增加分页。

## 在线页面接入范围

已核实入口：下一个假期、恐龙快跑、网速测试、2048、Qwerty Learner、渐变色、图片压缩、时间戳转换、头像生成、音频格式转换、加密工具、IP 查询、视频剪切、亲戚计算器、头像生成器、音频剪切、数字大写转换、中国高校排名。

18 个入口在本次 HTTP 检查中均返回 200，未返回 `X-Frame-Options` 或 `Content-Security-Policy` 限制头。**页面返回 200 不等于其中每项业务都已验收**：本次对原版 2048 键盘操作、数字大写转换 `1234.56 → 壹仟贰佰叁拾肆圆伍角陆分` 进行了浏览器功能实测，其余入口只核实了页面地址与响应。

部分原版页面还会嵌套其他网站，例如数字大写转换加载 `daxie.madebylesign.com`。其服务可用性、登录要求、付费限制和内部数据存储由原站决定。页面外提供「在新标签页打开」，关闭弹窗会销毁 iframe，停止页面运行。

新工程只构造已核实的 `https://widget.itab.link/<component>/index.html` 地址，使用组件白名单，不执行目录返回的任意脚本；不向原站传递 Google 令牌或原 iTab 登录凭据。扩展本身的脚本继续随包本地提供。Manifest 指定 `frame-src https://widget.itab.link`，远程页面使用 iframe sandbox；这次验证的是本地加载扩展，不代表已通过 Chrome 商店审核。

## 原版内置组件为什么不能直接 import

| 原包文件                                   | 作用与依赖                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| `chunks/staleAssetReload.lazy-DksV6goU.js` | 聚合大量 `./app/<component>/icon/*.vue` 卡片，依赖 Vue、工具函数和共享状态 |
| `chunks/widget-icon-item-DpoFEOpE.js`      | 原组件卡片包装及尺寸轮播；使用 Vue props、事件和 Element Plus              |
| `chunks/index-FjBLsWdN.js`                 | 通过模块映射按需加载原组件弹窗，或打开远程 iframe                          |
| `chunks/stocksCache-CNvbf2yR.js`           | 包含导航、设置、状态与浏览器通信；模块顶层访问扩展 runtime                 |
| `chunks/baseRequest-Yj83uNvm.js`           | 原后端请求、可选账号 token、签名及版本等处理                               |

这些是发布后的编译产物，不是可以直接放进任意 HTML 的 Web Components。复制单个文件会缺 Vue 运行时、状态容器、CSS、资源、事件总线及持久化约定；整体搬入又会带回原账号、统计和大量本次范围外的模块。

如果要进一步达到主页动态卡片和内部交互的 1:1，需要建立独立 Vue 宿主、逐个抽取组件依赖、适配 `baseConfig/navConfig` 与保存接口，再把组件数据汇入当前备份结构。适配应优先选择本地便签、待办、日历、倒数日等，再分别处理天气、热榜和电影等在线服务。PDF 和 AiPPT 的原版实现目前仍在这一待适配范围。

## Google 备份边界

- 主页中的原版入口 ID、名称、图标、所在分组、位置、尺寸与组件标识保存在现有主页状态中，本地 JSON 与 Google Drive 备份会包含它们。
- 原 iframe 的 localStorage、IndexedDB、登录态及内部内容属于第三方来源，当前没有可供宿主调用的统一导出/恢复协议，不会被自动打入主页备份。2048 的游戏进度也不应被误认为可以随主页跨设备恢复。
- 本地便签、待办和设置仍沿用现有完整备份实现。
- Google OAuth 仍需配置使用者自己的客户端 ID；本次没有真实 Google 账号授权、上传及跨设备恢复结果。
